## 2. 保存・状態管理

- 保存データは `useSyncExternalStore` で購読する。`getSnapshot` は保存文字列・`null`・固定のエラー値・（サーバー側）固定の読み込み中の値のいずれかを返し、毎回新しいオブジェクトを生成しない。
- 状態は「読み込み中・データなし・正常データ・読み込みエラー」を明確に区別する。
- `localStorage` 自体へのアクセスや `getItem` の例外は読み込みエラーとする。
- 同一タブでは `storage` イベントが発生しないため、保存成功後に明示的に更新を通知する。保存失敗時は通知せず、旧状態を維持する。
- 読み込みエラーからの再試行では、必ず読み込みを再実行する。
- 別タブ変更を検出した場合、既存のデータを上書きしない。

## 3. 日付処理

- 暦日差分は年月日から作る通し番号で計算し、DSTの影響を受けない。
- `Date.UTC` は0〜99年を1900年代として扱うため、年は `setUTCFullYear` で設定する。日付検証と暦日計算は同じ関数を使う。
- 日付変更のテストは固定日時またはテスト用の時計を使い、端末のシステム時刻は変更しない。

## 4. 追加テストケース

| ID | 操作・入力 | 期待結果 |
|---|---|---|
| T31 | 同一タブで保存成功 | 直後に記録・集計が更新される |
| T32 | 別タブの変更を検出 | 古いデータで上書きしない |
| T33 | 初回表示時間を測定 | 3秒以内。測定条件・結果・合否を記録する |
| T34 | 絵文字を含む習慣名 | コードポイント数で上限を判定する |
| T35 | 読み込みエラーから再試行 | データが正常なら復元される |
| T36 | 初回登録の保存に失敗 | 入力内容が維持される |

手動テストを実施できない場合は「未実施」と記録し、合格扱いにしない。
