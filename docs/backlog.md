課題提出後に検討する改善候補です。**いずれも未実装で、現在の MVP の範囲には含めません。** 着手する前に、要件の追補とユーザーの承認を経ます。

## B-01：日ごとの振り返りコメント

- 状態：未着手（課題提出後に検討）
- 受付日：2026-11-27
- きっかけ：公開版を実際に見た人からのフィードバック

### 寄せられた意見（要旨）

> 何をしたかコメントを書けると振り返りに役立つ。読書なら何ページまで読んだか、何を学んだかを記録できると、次回の再開がしやすい。歯磨きなどにはコメントは不要。

### 想定する機能

1. **日ごとの任意コメント**：その日の記録に、短いメモを付けられる（例：「120ページまで」「第3章の要点」）。書かなくても記録できる
2. **過去のコメントの閲覧**：直近7日間などから、過去のメモを読み返せる
3. **次回の再開支援**：間が空いたあとに開いたとき、最後に書いたメモを表示して、どこから再開すればよいか分かるようにする

### 意見から読み取れる要件

- コメントは**任意**にする。歯磨きのように、メモが不要な習慣では入力欄が邪魔にならないこと（1タップで記録できる今の操作を損なわない）
- 再開を助けることが主な目的。コンセプト「継続より、再開する力。」と合っている

### 検討が必要な点

| 観点 | 内容 |
|---|---|
| 要件との関係 | 要件定義書のストーリーマップでは、v1.0 に「過去編集・理由」がある。コメントの位置づけをどこに置くか（今日だけ書けるか、過去の日にも書けるか）を決める |
| データ形式 | 保存形式（`restart:v1`、`schemaVersion: 1`）の変更が必要。新しいバージョンへの移行処理と、移行に失敗した場合でもデータを消さない仕組みを用意する |
| プライバシー | コメントは今の記録と同じく localStorage に暗号化なしで保存される。個人情報や機密情報を書かないよう、入力欄の近くで案内する |
| 入力の制限 | 文字数の上限、改行の扱い、空白だけのコメントの扱い。表示は React の通常のテキスト描画とし、HTML として挿入しない |
| 画面 | スマートフォンで、記録ボタンの操作を邪魔しない置き場所（折りたたみなど）。320px でのレイアウト |
| 習慣ごとの要否 | 「コメントを使う／使わない」を設定にするか、常に任意の入力欄にするか |
| テスト | 保存・復元・移行・破損データ・文字数上限・読み上げのテストを追加する |

## B-02：ブラウザテストスクリプトの改善

- 状態：未着手（課題提出後に対応）
- 受付日：2026-11-27
- きっかけ：公開URLでのブラウザテスト（[test-report.md](test-report.md) の「公開環境での確認」）

アプリの機能は変えず、テストの信頼性と記録の分かりやすさを上げるための改善です。

| # | 課題 | 改善案 |
|---|---|---|
| 1 | Chrome を終了させた直後に Chrome が一時プロファイルへ書き込み、削除に失敗して実行スクリプトの終了コードが 1 になった | Chrome のプロセスが完全に終わったことを確認してから削除する。削除に失敗しても、テストの合否とは分けて報告する（終了コードにはテスト本体の結果を使う） |
| 2 | 公開URLに向けて実行しても、固定の未実施リストに「T33-公開URL 未実施（デプロイ未承認のため）」が表示される | 対象URLに応じて未実施リストを変える（公開URLに向けた実行では表示しない） |
| 3 | T33 は3回の中央値だけを保存し、各回の値が残らない | 各回の値（ready・load・FCP）も `results.json` に保存する |

対象ファイル：`e2e/run-e2e.sh`、`e2e/cdp-check.mjs`（公開URL向けの実行手順もあわせて整理する）
